## Built around the crown

**Keep the anatomy you chose.** Imported library teeth retain their millimetre scale instead of
being stretched to textbook proportions. DentCraft seats the tooth, adapts the cervical region,
and reports extra lift or a fallback so you can review the result.

**Give the design room to breathe.** A floating wizard, compact toolbar and Objects panel put
the model at the centre. Pin the Expert strip, select design parts, and apply settings across
teeth with one undoable operation.

**See what the geometry is doing.** Follow the margin, inspect the insertion axis, section the
inner surface and review material thickness. Geometry uses double precision; automated tests
include tilted, noisy preparations and true 3D distances inside triangles.

## Why DentCraft

From the first margin point to the exported crown, every design decision deserves a clear place
in the workspace. DentCraft brings that process into an open, inspectable tool built by people
who work in dentistry—and shaped by the technicians, clinicians and developers who use it.

| | |
|---|---|
| 🦷 **The workflow you know** | A guided crown-design path: margin, insertion axis, cement gap, anatomy, contacts, thickness and export. Focused tools with visible feedback. |
| 🎯 **Precision you can inspect** | Double-precision geometry, regression tests for difficult inputs, and design limits taken from the material you choose. |
| 🛡️ **Recovery built in** | Memory-safe Rust, guarded background jobs, autosave and recovery prompts help protect the workflow. |
| 💻 **Runs everywhere** | One codebase for Windows, macOS and Linux, plus a headless command line (browser build planned). |
| ⚡ **Local design tools** | Margin detection, insertion-axis estimation and crown fitting run on your own machine. Broader automation is on the roadmap. |
| 🌍 **Open and multilingual** | Free to use, study and improve under MIT OR Apache-2.0. Right-to-left languages, including Arabic, are on the roadmap. |

## The design workflow

A case lists the teeth to restore and the restoration on each. DentCraft builds the plan from that:
shared steps first, then the steps each restoration needs, tooth by tooth.

**Single crowns are the supported end-to-end workflow in 0.2.1.** The table below describes the
workflow model; it does not mean every restoration type is implemented. Bridges, pontics,
copings, inlays, onlays and veneers remain on the [roadmap](ROADMAP.md).

| # | Step | Crown | Coping | Inlay / Onlay | Veneer | Pontic |
|---|---|:-:|:-:|:-:|:-:|:-:|
| 1 | Scans | ● | ● | ● | ● | ● |
| 2 | Orientation *(optional)* | ● | ● | ● | ● | ● |
| 3 | Margin line | ● | ● | ● | ● | |
| 4 | Insertion axis | ● | ● | ● | ● | |
| 5 | Inner surface (cement gap) | ● | ● | ● | ● | |
| 6 | Anatomy | ● | | ● | ● | ● |
| 7 | Pontic base | | | | | ● |
| 8 | Occlusion & contacts *(optional)* | ● | | ● | | ● |
| 9 | Sculpt *(optional)* | ● | ● | ● | ● | ● |
| 10 | Connectors *(bridges)* | ● | ● | | | ● |
| 11 | Minimum thickness | ● | ● | ● | ● | ● |
| 12 | Finish & export | ● | ● | ● | ● | ● |

Material presets (zirconia, lithium disilicate, PMMA, wax) set the cement gap, margin seal,
minimum thickness and connector size. Teeth use FDI notation (ISO 3950).

## Download

**[DentCraft 0.2.1 for Windows](https://github.com/elnajar1/DentCraft/releases/tag/v0.2.1)**: a single
`.exe` with nothing to install. The prerelease includes a separate command-line executable and
SHA-256 checksums. It designs a single crown from margin to STL; see the
[changelog](CHANGELOG.md) for what's in it and its known limitations. macOS and Linux users build
from source below.

## Build from source

Install a recent stable [Rust](https://rustup.rs) toolchain, then:

```sh
git clone https://github.com/elnajar1/DentCraft.git
cd DentCraft
cargo run --release -p dentcraft                  # desktop app
cargo run --release -p dentcraft-cli -- --help    # command line
cargo test --workspace
```

Linux needs the usual GUI development packages (`libxkbcommon-dev`, `libgtk-3-dev`).

| Crate | Role |
|---|---|
| [`dentcraft-mesh`](crates/dentcraft-mesh) | Triangle mesh, topology, queries and repair |

| [`dentcraft-case`](crates/dentcraft-case) | Case model: teeth (FDI), restorations, bridges, scans, materials |
| [`dentcraft-workflow`](crates/dentcraft-workflow) | The design wizard: steps per restoration and session state |
| [`dentcraft-cli`](crates/dentcraft-cli) | Headless command line |
| [`dentcraft`](crates/dentcraft) | Desktop application (egui + wgpu) |

## Contributing

Dental technicians, dentists, students and developers are all welcome. Start with
[CONTRIBUTING.md](CONTRIBUTING.md); the clean-room rules in [AGENTS.md](AGENTS.md) apply to every
change. Technicians can help most by describing how they design a case today: open a
[workflow request](https://github.com/elnajar1/DentCraft/issues/new?template=workflow_request.yml).
Never share patient data.

If you use DentCraft in research or teaching, please cite it ([CITATION.cff](CITATION.cff)).
